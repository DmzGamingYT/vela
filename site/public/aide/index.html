Aide

Installer, ouvrir, comprendre.

Les builds ne sont signés par aucun certificat Apple ou Windows. Voici ce que chaque système demande au premier lancement, et ce que l’installation fait.

macOS — ouvrir un build non signé

Le fichier Vela-0.3.41-universal.dmg est universel : il couvre Apple silicon et Intel dans un seul .dmg. Gatekeeper refuse la première ouverture parce que l’application n’est ni signée ni notarisée : aucun certificat Developer ID n’est acheté, et il n’existe pas de notarisation Apple. Le build universel est publié ; l’essai sur une vraie machine Intel reste à faire.

  1. Ouvrir le .dmg, puis glisser Vela dans le dossier Applications.
  2. macOS 15 et plus : lancer Vela depuis Applications, puis ouvrir Réglages Système › Confidentialité et sécurité et cliquer « Ouvrir quand même » à côté du message concernant Vela.
  3. macOS 14 et moins : dans le Finder, faire un clic droit sur Vela, choisir « Ouvrir », puis confirmer.

Si macOS refuse encore, vérifier le message dans Réglages Système › Confidentialité et sécurité. En dernier recours, dans le Terminal :

xattr -cr /Applications/Vela.app

Une installation silencieuse n’est pas possible sans signature : macOS ne remplace pas un bundle non signé à la place de l’ancien ; chaque version passe par son .dmg.

Windows — SmartScreen

L’installateur .exe n’est pas signé par un certificat commercial. SmartScreen affiche donc un avertissement au premier lancement, avant même l’installation.

  1. Lancer Vela-0.3.41-x64.exe.
  2. Dans la fenêtre bleue, cliquer « Informations complémentaires ».
  3. Cliquer « Exécuter quand même », puis suivre l’installation.

Linux — AppImage ou .deb

L’AppImage se lance sans installation ; le paquet Debian convient à Debian, Ubuntu et leurs dérivés. L’AppImage de cette version utilise encore le runtime FUSE 2 : sur Ubuntu 22.04 et plus récent, la bibliothèque peut manquer.

  1. Rendre l’AppImage exécutable, puis la lancer.
  2. Si le message « AppImages require FUSE to run » apparaît, installer la bibliothèque FUSE 2 : libfuse2 sur Ubuntu 22.04, libfuse2t64 sur Ubuntu 24.04 et plus. Ne jamais installer le paquet nommé fuse, qui casse GNOME.
  3. Debian et Ubuntu : installer le paquet .deb, qui n’a pas besoin de FUSE.
  4. L’AppImage, macOS et Windows préparent la mise à jour ; le paquet .deb se remplace à la main. Le tableau des mises à jour détaille chaque format.
chmod +x Vela-0.3.41-x86_64.AppImage
./Vela-0.3.41-x86_64.AppImage
sudo apt install libfuse2
sudo apt install libfuse2t64
sudo apt install ./Vela-0.3.41-amd64.deb

Les commandes ci-dessus se copient d’un clic. Le .deb demande les droits d’administration ; l’AppImage non.

Connexion Google

Google peut refuser l’identité d’un navigateur qui n’est pas Chrome. Vela n’imite pas Chrome au-delà du nécessaire : la connexion passe par le navigateur système, et Vela n’importe jamais de cookies.

  1. Dans Vela, clic droit sur le lien › « Copier l’adresse du lien ».
  2. Ouvrir Chrome ou Safari, coller l’adresse, puis se connecter à Google.
  3. Revenir à Vela : la session Google reste celle du navigateur système.

Les marque-pages, eux, s’importent. Dans Chrome : menu ⋮ › Favoris et listes › Gestionnaire de favoris › ⋮ › Importer des favoris. Dans Safari : Fichier › Importer depuis › Google Chrome. Aucune session ni aucun cookie n’est transféré.

Extensions et synchronisation

Les extensions du Chrome Web Store ne sont pas prises en charge. La synchronisation de compte Vela n’existe pas non plus : il n’y a pas de compte. Vos espaces, vos notes et vos réglages restent dans le dossier de données de la machine, décrit sur la page Confidentialité.

Mises à jour

Tous les formats vérifient les versions douze secondes après le démarrage, puis toutes les trois heures, au retour de veille et au retour du focus (au plus toutes les trente minutes). Ce qui est téléchargé et installé dépend ensuite du format.

Mises à jour par plateforme
Format Téléchargement Installation
macOS .dmg Le .dmg de la nouvelle version est téléchargé en arrière-plan et son empreinte SHA-512 est vérifiée. Le bouton Installer ouvre l’image ; glisser Vela dans Applications. macOS n’installe pas un bundle non signé à votre place.
Windows .exe L’installateur est téléchargé en arrière-plan. Il s’installe à la fermeture de Vela. « Redémarrer et installer » le lance tout de suite.
Linux AppImage L’AppImage est téléchargée et son empreinte est vérifiée. Vela remplace l’AppImage au redémarrage si le fichier est accessible en écriture ; sinon il l’affiche pour un remplacement manuel.
Linux .deb La version est vérifiée, mais aucun paquet n’est installé automatiquement. Le .deb se remplace à la main avec apt ; les données de Vela restent en place.

Depuis la 0.3.22, sur macOS, le manifeste qui annonce une version doit être signé : Vela vérifie sa signature Ed25519 avec la clé publique épinglée dans son code, puis compare l’empreinte SHA-512 du .dmg téléchargé. Un manifeste non signé est refusé ; l’installateur reste disponible sur la page Releases.

Le rythme du contrôle se règle dans Réglages › Mises à jour › Vérification automatique : au démarrage et toutes les trois heures par défaut, une fois par semaine, ou jamais. Le bouton « Vérifier les mises à jour » reste disponible dans les trois cas.

Le contrôle auprès de GitHub est décrit ligne par ligne sur la page Confidentialité.
